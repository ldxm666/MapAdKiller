# 2.3.5 发布验证

测试日期：2026-11-11。对比公开版本 2.3.4，基准提交 `adfe2bda2066fa18e7c9ab758c87f7a44d9a4271`。结果对应本次发布的最终产物；机器可读汇总见 [validation-2.3.5-results.json](validation-2.3.5-results.json)。

## 高德首页问题的原因与修复

本次根据国内 17.02.0.2010、Play 17.02.2.2014 的 DEX 与设备运行记录核对原生面板状态机，没有对全局布局或触摸事件做猜测性拦截。

- 原生 `SlideContainer` 的最小高度、锚点 setter 会额外加入拖动栏高度；透明高度 setter 还会加入状态栏高度。把 setter 输入直接与 getter 结果比较，会误判为始终需要更新，反复触发布局。现在按原生实际偏移比较，只在几何确实变化时写入。
- 全屏和拖动期间强制重设面板，会干扰原生隐藏、恢复及动画状态。现在对 `HIDDEN`、`HIDDEN_EMPTY`、拖动和未结束的原生动画放行，等面板稳定后再处理需要的高度变化。
- 反复滑动可能留下额外锚点，导致面板停在中间。现在使用原生位置计算方法核对实际位置，必要时在空闲状态恢复标准锚点；位置正确时不重复调用 setter。
- 工具宫格和底栏开关会改变内容高度。现在在原有组件范围内失效并重算高度，合并下一帧更新，补齐宫格重新开启、全屏往返和连续拖动后的恢复路径。

## 重复执行

在仓库根目录执行，`MODULE_BUILD_DIR` 是 `app/build.ps1` 生成的构建目录，`DEVICE_SERIAL` 由测试者明确指定。原始地图 APK、签名密钥不随源码发布。

```powershell
pwsh -NoProfile -File app/build.ps1
pwsh -NoProfile -File tests/run-android.ps1 -BuildDirectory MODULE_BUILD_DIR -Serial DEVICE_SERIAL
python tools/verify_module.py --ModuleApk output/MapClean-lsp-v2.3.5.apk --ExpectedVersion 2.3.5 --ExpectedVersionCode 2305
python tests/run-production.py --help
python -m unittest discover -s tests -p test_check_anchors.py -v
```

生产回归为 `tests/run-production.py` 提供完整模块及四类内置产物，实际参数名见其帮助；native 测试入口见 [回归台账](REGRESSION.md)。UI 检查顺序为：冷启动 → 开/关宫格三轮 → 地图全屏/恢复三轮 → 连续展开/收起五轮 → 重开验证。额外单独检查全部底栏隐藏时的宫格位置，避免将快速连续手势识别失败误判成状态机错误。

原始截图、日志、设备标识、个人配置、地图原包及私有探针只保留在被 Git 忽略的工作目录，不放入公开源码包。测试结束恢复本轮临时设置，保留用户原分类和底栏选择；未用旧数据库覆盖当前配置。

## 验收边界

- 本轮最终包的实机与 ART 环境为 Android 16 / HyperOS 3，未重新执行 Android 13 的最终包回归。2.3.4 的 Android 13 历史记录仍可查阅，不能替代本轮验收。
- 完整模块通过 LSPatch 宿主验证及生产 DEX 回归，**不等于已完成官方签名宿主的外部 LSPosed 注入验收**。独立模块已安装，框架仍保持测试前的关闭状态与作用域。
- 高德国内与 Play 包名相同，测试采用保留数据的覆盖安装切换，并最终恢复国内最终包。不是清空数据后的全新安装测试。
- 标注类别来自宿主原生样式目录。高德分类需重开地图；腾讯分类仅在主页应用，搜索、导航恢复原样式。通用楼宇、未知或混合用途图标仍可能保留，不能保证所有建筑都能正确归类。
- HyperOS 灵动岛仍有未解决反馈，ColorOS 未完成实机验收；百度没有真实待支付订单。没有把系统卡片策略和支付策略测试写成这两项问题已全部解决。
- POCO F3 / MIUI 14 / Android 13 的安装报告、车机适配及真实道路自动巡航仍需相应条件下的反馈。
