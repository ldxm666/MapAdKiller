## 4. 根因与证据（结论，不必重跑）

**定性：高德 17.02.0.2010 不存在任何第三方广告 SDK。** 8 个 dex、73,638 类，`pangle` / `kwad` / `gdt` / `mobads` / `sigmob` / `mintegral` / `qq.e` / `tanx` / `topon` 等全部 0 命中；`bytedance` 只有一条邮箱字面量，`gdt` 全是 `/autonavi/gdtaojin/`。广告是高德自有的阿里妈妈通道 + 云控下发的素材与频次，本地原生 View 渲染。

开屏广告的完整链路：

```
tryShowSplashView(scene, src) → g.o(scene, src)
  ├─ y96.g(scene, src)               就绪位，a==1 ⇒ NO_SPLASH
  ├─ SplashFrequencyController.a/b   云控频次
  └─ 时限>0 → g$e → xc5.run() → ISplashScreenService.fetchRealTime()
        └─ SplashScreenServiceImpl.a() → yc5.run()   裸 HttpURLConnection
  └─ g.i(scene, elapsed) → yg2.i(scene) 取 k66 → v76.run()
        ├─ g.d() 建 SplashContainerView，g.m(ctx)
        ├─ k66.A == "static_image" → ImageSplashView / "video" → VideoSplashView
        └─ ISplashUI.getSplashView(...) → addView → g.startAd() → play()
```

素材来源有两条独立通道：预下载（`AlimamaRequestHolder.sendSplashScreen` → `ws/valueadded/alimama/splash_screen`）与实时（`yc5.run()` → `ws/aos/alimama/splash_screen_rt`）。2.3.5 只覆盖了前者与 `y96` 就绪位，后者结构上不经过它们。

真机复现（2026-11-13 00:46，2210132C / Android 16 / 2.3.5 内置版）：把 `alimama_splash_off` 置为 false 后冷启动，`alimama_blocked method=sendSplashScreen` 消失，高德当场新下了一张 **506,821 B** 的开屏图（`files/splash/i_1e925026203c62ded055b2ad6f9dbf48`，此前不存在）；`y96` 在 0.5 s 收尾所以视图没挂上。⇒ 请求通道是活的、素材会落地，**拦请求不足以"抹除"**。
