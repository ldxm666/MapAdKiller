## 腾讯：实现与能力边界

实现：`app/src/io/github/ldxm666/tmapclean/TmapAnnotations.kt`。

1. 在 `MapBaseView.onAttachedToWindow / showViews / setHomeView` 后绑定渲染器。首次引擎未就绪仍保留观察对象，按 80 / 350 / 1,200 ms 有限重试，旧任务用代次失效，不启动永久轮询。
2. 每次刷新重新解析渲染器，同一 `MapBaseView` 换引擎后恢复旧对象并应用新对象。
3. 保留原生 `setContentVisible` 的完整掩码、结果和异常，原调用仅一次；成功后记录原生意图，并单独修改标注位 `8`，不因 `ALL` 或混合掩码误关道路、地形。
4. 写入失败不误记为成功，后续可重试；原生本来关闭的标注不被强行打开。
5. 基础标注仅应用主页，搜索等非主页恢复原生策略，回主页再应用用户设置。

**该功能仍是基础标注整层控制，不是普通 POI 独立分类过滤。** 腾讯 11.7.0（6013）的位 `8` 同时包含 POI、路名和地名，设置页已说明。富信息、3D POI、地标等独立开关继续保留，不能用本轮基础标注测试代替其全部视觉验收。关闭文字标注后，实际道路、地形和楼块保留。

## 系统卡片：已修正的误拦截

### 高德

`AmapSubprocess.kt` 不再停止 `DesktopWidgetService.onStartCommand`。原包证明该共享服务会发布 `category=navigation`、带 `com.autonavi.minimap.navigating=true` 的持续前台通知，不能视为纯桌面广告服务。

不再跳过 `HiBoardCardProvider.initCardWidget`；原生实现会初始化 OPPO 卡片 SDK，保留完整生命周期。标准小组件周期刷新仍按用户省电开关处理，厂商 action 和创建、删除、选项变更等广播保留。

### 百度、腾讯与设置说明

`BaiduPower.kt` 不再停止共享 `NotificationService.onStartCommand`，原包该服务含用户路况通知刷新和取消逻辑。小组件更新仅精确匹配 `android.appwidget.action.APPWIDGET_UPDATE`，不再使用 `endsWith` 误伤 `miui.appwidget.action.APPWIDGET_UPDATE` 等厂商广播。

高德、百度设置说明同步更新。其他独立推送、任务和省电开关未整体取消。腾讯现有钩子未发现同类通知服务停止或厂商广播后缀过滤，本轮未无依据新增系统能力 Hook。
