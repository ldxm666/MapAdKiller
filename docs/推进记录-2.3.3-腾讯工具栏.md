## 首次上拉只有第一排：两个独立根因

1. `expandGridOnce()` 为新一批工具数据调用原生 `a(1f)` 时，上一批数据的 `gridForced` / `ratioPinned` 仍为真。调用被模块自己的高度守卫接住，重用了旧的一排高度。现在先释放旧守卫，让新数据完成一次原生完整布局，然后重新记录满行高度。
2. 收起态的一排是腾讯动画的临时尺寸。之前在 ACTION_DOWN 量到了它，又将其当作下一次展开的最大高度。现在通过 `expandedGeometryReady()` 判断：完整布局未就绪时保留原生中档上限；就绪后才按内容收紧范围。

回归覆盖原生数据高度 `264 → 631 → 264 → 631`，不靠重启清缓存。原生第一排中的“更多”是适配器可合成的入口，出现它不代表原生数据一定只有五项，不能据此误判或改写用户排序。

## 上拉闪动与紧凑上限

- `HomePageCardView$HomePageCardContainerView` 不是面板本体。修正以前的子串识别，避免将内容容器当成 SlideCardView 量高度。
- 工具高度与透明度一起固定在完整状态，避免一帧执行部分原生布局、下一帧再补完整布局。
- 移除 400/900/1500/2200/3000 ms 的多次重压，改为原生档位稳定后合并到一帧处理。
- 推荐信息流关闭时，以原生中档与有效内容共同限制上限；收起档不改，信息流开启时保留原生展开范围。
- 原生 `HomePageCardAdapter.a(F)` / `ewt.a(F)` 是中档到高档的过渡。紧凑模式将正进度保持为零，低档收起进度保留。
- 到顶仍有轻微位移的来源之一是原生 `HomeRecycleView` 的边缘拉伸。只对已确认的首页列表关闭 overscroll；重新显示信息流时恢复该列表原来的策略。没有替换触摸监听器、工具点击回调或全局 RecyclerView 行为。

录屏对照：同一设备、同一固定工具区域、6 次上拉（900/180/500/250/750/200 ms），画面绝对像素差 P95 从约 21.60 降到 2.15。该指标用来比较工具区域是否被拉伸，**不是帧率或商业级流畅度认证**；screenrecord 只记录变化帧，不能将视频 FPS 当应用渲染 FPS。

## 原生功能与配置配对

- 工具仍使用腾讯 `gaa` / `gbt` / `gbr` 的真实 Cell 与原生视图，仅复制适配器输入后筛选，不用自绘图标宫格替代点击入口。
- 二排/三排的原生视觉裁切分别补偿 30/40 dp，并随实际工具数量与密度变化；不使用统一的屏幕百分比当展开高度。
- `TmapHomeFav` 将通勤与推荐区块分别识别、隐藏、恢复，信息流关闭不会再连带隐藏“设置家/设置公司”。延迟挂载的 Litho 区块允许有限次数重新识别。
- `TmapMapIcons` 仅处理首页原生地图控件，保存并恢复控件自己的 VISIBLE/INVISIBLE/GONE；与 POI 开关分离。
- `TmapEntry` 在腾讯原生“首页/我的”保留原点击行为，额外提供长按设置入口。悬浮球关闭并冷启动后仍可找回设置。
- `Cfg.write()` 成功后触发本进程配置刷新，避免本地写入成功但当前界面不更新。

## 两套框架同时启用时的防重复安装

实机同时安装 LSPosed 模块与 LSPatch 内置版。两个 ClassLoader 各自的静态布尔值不能阻止重复安装，两个状态缓存也不能安全恢复对方遮蔽后的原生值。

现在：

1. 原生 UI 类未就绪时不锁定 INSTALLED，等待 Application 回调重试。
2. 内置模块在加载时设置进程级标记；不能只查 `assets/lspatch/config.json`，因为 LSPatch 会替换 AssetManager。
3. 通过同一进程 `System.getProperties()` 的同步所有权记录，确保界面钩子只装一份。
4. 内置进程由 LSPatch 副本负责，LSPosed 副本记录 `skip_ui reason=embedded_owner`。未内置的宿主仍由模块版负责。
5. 非所有者不绑定设置服务、不覆盖最终 UI 挂钩报告。

实机已观察到内置版 `ok=95 miss=0`，LSPosed 的 UI 路径正确跳过。该计数是界面钩子安装结果，不能代替每个地图效果的视觉验证。

## POI / 3D 地标的真实原生映射

通过 DexSQL MCP 对当前原厂 APK 查询并解码，不按方法名猜测 SDK 接口。JADX MCP 虽已注册，本机 8650 插件未连通；本轮分析使用的是实际可用的 DexSQL。

| 配置 | 腾讯上层接口 | SDK 真实入口 |
|---|---|---|
| POI 富信息 | `setPOIRichEnable` | `setFeatureEnable(PoiRich, Z)` |
| 应用 POI 富信息 | `setAppPoiRichEnabled` | `setFeatureEnable(AppPoiRich, Z)` |
| 建筑 POI 富信息 | `setBuildingPoiRichEnable` | `setFeatureEnable(BuildingRich, Z)` |
| 3D POI | `set3DPOIEnable` | 独立的 `set3DPOIEnable(Z)` / nativeSetPOI3DEnable |
| 3D 地标 | `setLandmarkEnable` | 独立的 `setLandmarkEnable(Z)` / 地标 SDK 路径 |

SDK 具体控制器是 `com.tencent.mapsdk2.internal.controllers.f`；控制器准备入口为 `com.tencent.mapsdk2.api.TencentMap.getMapStatusController()`。场景/样式可能直接调用 SDK 绕过上层腾讯封装，因此两层都需要覆盖。

保存真实原生请求，用线程局部状态区分“原生请求 true 被遮蔽成 false”和“原生主动关闭”。开关重开时恢复原生请求，而不是无条件强制开启。

验证边界必须保留：

- 实机将前两项关闭/开启后，SDK getter 回读分别为 false/true。
- 3D POI 与地标已命中独立 SDK setter；SDK 没有对应的可用布尔 getter，本轮未完成有代表性地标场景的视觉消失/恢复验收，诊断明确记录 `visual_pending`。
- `MapAnnotationPoi3D` 不是 `nativeSetPOI3DEnable` 的等价回读，测试确保没有用错这个枚举。
- 普通底图店名、道路文字、酒店价格气泡及普通立体楼块并不等同于上述五类效果。本轮没有添加“关闭全部 POI”或“关闭所有立体建筑”的能力，不得宣称这些全部已消除。
- 用户当前建筑富信息、3D POI、3D 地标为关闭状态，已保留；前两项富信息恢复到测试前的允许显示状态。
