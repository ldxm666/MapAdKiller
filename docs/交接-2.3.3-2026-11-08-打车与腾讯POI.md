## 4. 白屏：已解决的具体问题与验证边界

问题是 LSPatch 覆盖安装后，原版高德的 linker namespace 仍引用上一安装目录。原生依赖加载失败后高德调用 `System.exit(0)`，外观表现为持续白屏。不是靠拦截退出或跳过初始化解决。

改动：

- 重写 `app/src/io/github/ldxm666/mapadkiller/AmapLibDirFix.kt`。
- `AmapHooks.install()` 的普通启动路径现在也调用修复，不再仅依赖首次升级/基线采集分支。
- 从当前 PMS 取得 `ApplicationInfo.nativeLibraryDir`。
- 使用 `Runtime.load0(Class, String)`，以宿主 `com.amap.AppInterfaces` 的 Class 进入宿主 namespace，按 DT_NEEDED 拓扑序加载 9 个依赖：`c++_shared / openssl / zstd / amapnsq / amapkvd / cJSON / opus / nui / OSL_MNN`。
- 当前目录变更时才预载；全部成功后才写 `<dataDir>/cache/mapclean-native-dir-v2`。失败不写成功标记，不锁死下一次重试。

实际证据：

| 场景 | 结果 | 证据前缀（均在 `.agent_work/goal-233/`） |
|---|---|---|
| 启动修复包首次覆盖安装 | 地图正常显示，PID 持续存活；修复 9 个依赖约 14 ms | `startup-fixed-first-*` |
| 启动修复包再次冷启动 | 正常显示，目录标记命中，不重复预载 | `startup-fixed-cold2-*` |
| 同一启动修复包再次覆盖安装 | 新安装目录下首次启动正常；修复约 11 ms | `startup-fixed-cover2-*` |
| 新打车包覆盖安装首启 | PID 4841，观测到 10.672 s 仍存活，地图正常显示；修复约 11 ms | `taxi-first-*` |
| 交接前关闭临时调试再冷启动 | PID 20464，观测到 10.984 s 仍存活，地图正常显示 | `taxi-handoff-*` |

新打车包首启 `am start -W` TotalTime 1596 ms；交接前冷启动 1914 ms。这只是 Activity 首帧指标，**不能等同地图完全就绪耗时，更不是性能提升比例**。

## 6. 内置版配置持久化：已修并验证迁移

发现两处相互关联的问题：

1. 启动早期无宿主 Context 时，`Config.prefs()` 把 remote 永久缓存，后续 Context 就绪也不迁移到 local。
2. `CfgStore` 文档说 local 为准，但读取实际让 remote 覆盖 local；远程镜像写失败时旧值会盖掉成功的本地写入。

- 启动早期 remote 仅暂用，按 500 ms 节流等待本地 Context；之后导入缺失旧配置，保留已存在的本地值。
- 内置模式 remote 打底、local 覆盖；LSPosed 模块模式保留 remote 优先。
- `AmapPanel.write/writeInt` 在内置模式不再因 service 写成功就提前返回，统一经过本地权威写入路径。
- `CfgStoreTest.java` 覆盖旧远程值、本地新值、类型、一次迁移、空 remote 后重试等场景。
